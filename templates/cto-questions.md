# The day-one CTO questions

Record them in a table: question, one-line answer, the step that proved it, the link to the evidence.

| # | Question | Answer | Proved in | Evidence |
|---|---|---|---|---|
| 1 | What does this system do for the business, in one sentence, and what breaks revenue if it stops? | | | |
| 2 | Where is the list of everything that exists, and who owns each item? | | | |
| 3 | Which numbers does leadership run on, and can two people pull the same number and get the same answer? | | | |
| 4 | What runs every day without anyone watching it, and how would we know it stopped? | | | |
| 5 | Which credential, if leaked or rotated, takes down the most? Who can see sensitive data today? | | | |
| 6 | Who are the single points of failure, and what did each of them build alone? | | | |
| 7 | What is the oldest known defect still open, and why is it still open? | | | |
| 8 | What did we build ourselves that a vendor feature already does, and what do we pay a vendor for that we built around? | | | |
| 9 | What is still running on the platform we are leaving, and what is the date it goes dark? | | | |
| 10 | What is the next hard deadline the system faces (API deprecations, token expiries, contract renewals)? | | | |
| 11 | How does a change get made today: who asks, who approves, who tests, where is it written down? | | | |
| 12 | What would a competent outsider need to run this for a month if the team disappeared? | | | |
| 13 | What are the three fixes that reduce risk the most for the least work, and who can do them this month? | | | |
| 14 | What should we stop doing? | | | |
